# M2 实施与验收记录

目标是让工单和 Coding 经过同一工具入口。Coding 文件和测试运行在受限 Linux 容器中，由控制平面验证结果并保存审计。

| 步骤 | 实现内容 | 本步通过条件 | 状态 |
| --- | --- | --- | --- |
| M2.1 环境与固定镜像 | Docker 预检、摘要固定的 Python 基础镜像、锁定 pytest 依赖、最小隔离探针 | 引擎不可用明确拒绝，真实容器确认非 root、只读根、无网络和资源限制 | 完成，13 项测试通过 |
| M2.2 隔离执行适配器 | 每次调用独立 tmpfs 工作区、任务限额快照、容器内文件操作、结构化 pytest、输出和时限预算、容器回收 | 文件和测试只接触本任务工作区，超时和输出超限后无运行容器 | 完成，累计 31 项相关测试通过 |
| M2.3 统一 Gateway 与审计 | 共用工具注册、严格 Schema、资源策略和持久化调用记录 | 拒绝发生在派发前，工单与 Coding 均可按任务读取审计 | 完成，12 项专项测试和已有 62 项回归通过 |
| M2.4 Coding 完整切片 | 脚本模型修复真实代码、运行 pytest、控制平面独立验证、CLI 演示 | 初始代码失败，修改后测试和独立合同均通过，跨进程可读结果 | 完成，18 项演示与 Gateway 测试通过 |
| M2.5 攻击与收尾 | 路径/链接/宿主隔离/网络/间接执行/预算用例、回归和操作文档 | 完整自动测试、真实 Docker 集成测试、M1 回归通过，资源清理已核对 | 完成，全部 96 项测试通过 |

按表中顺序推进，每步先运行对应测试再继续。需要登录、接受条款或调整 Docker Desktop 设置且无法自动完成时，暂停并交给操作者。

M2 的文件写入权限只覆盖预先分配的临时 Coding 工作区。该权限由可信控制平面授予。外部业务写入继续沿用 M1 的人工审批。测试代码及其间接启动的进程都留在同一容器限制中。
