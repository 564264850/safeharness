# SafeHarness 当前定位与求职展示评审

评审日期：2026-11-12。依据当前源码、Pico 本地对照、R3/R4 证据和本轮隔离探针。当前源码与 R4 验收指纹一致；本轮没有重跑完整测试或修改生产源码。

2026-11-13 更新：下述验证真实性问题已按 [R5](verification-truth.md) 修复并重新验证。本文保留评审当时的发现和历史数字，当前证据以 R5 记录为准。

## 结论

适合写入 AI 应用工程、Agent 平台、Python 后端方向的个人项目。建议定位为“自主实现核心运行时的 Agent 安全执行与恢复框架”。已有完整的受控执行闭环、真实模型接入和故障证据，属于有工程深度的个人项目；尚不足以声称企业生产平台、大规模部署、通用 exactly-once 或新的安全算法。

## 底层职责

| 层 | 实现 | 价值与边界 |
| --- | --- | --- |
| 组装与循环 | Harness、Runtime | 单一循环、明确终态、审批暂停、验证后完成；当前同步串行 |
| 模型与上下文 | ModelClient、ToolCallingAgent、ContextManager | 统一消息边界、完整工具消息组、预算与历史压缩；字节预算而非精确 token，尚无长期记忆 |
| 工具控制 | ToolGateway、ToolSpec、严格参数与范围 | 授权先于执行，模型不能决定权限；当前工具注册和场景仍较固定 |
| 调用身份 | InvocationLedger、AuditLog、Trace | task/run/call/attempt/operation/产物分离，派发前登记及证据关联 |
| 审批与副作用 | 参数摘要、独立操作员、业务幂等回执 | 同任务多次审批，批准后回填结果并继续队列；落地于当前工单适配器 |
| 检查点 | 私有 JSON、配置指纹、generation/owner、revision | 保存上下文、队列及文件快照；显式恢复，未知结果安全停止；没有自动租约与 reaper |
| 环境 | DockerSandbox、CodingWorkspace | 隔离代码执行、资源约束、回收确认；Docker 和内核提供基础隔离能力 |
| 服务和验收 | FastAPI、SQLite/PG、Evaluation Runner、verifier | 归属/角色检查、持久化、开发矩阵；没有生产容量或独立保留集成绩 |

核心运行逻辑在 SafeHarness 内实现，没有把 Pico/pi/LangGraph 当作实际 Agent 循环依赖。Pico/pi 等提供设计参考。自研贡献是协议设计、控制面实现、适配和验证；Docker、数据库、Pydantic、FastAPI、DeepSeek、OpenJudge、A.I.G 等属于外部能力。不能将这些外部项目本身写成自研成果。

## 可以展示的证据

- 283 项回归通过，包含真实 Docker、PostgreSQL，0 跳过。
- 固定合成开发验收 120/120：Coding 30、工单 30、攻击边界 40、故障 20。它们不是 120 类独立风险或生产认证。
- 真实 DeepSeek 完成两次审批及对应回读；评审者来自宿主测试操作员，模型没有审批权限。
- 真实进程退出后核对工单回执并继续读取，业务写入仍为 1 次。
- 独立安装包验证、迁移备份和源码指纹；CI 配置存在，远程 CI 尚未运行。

## 本轮新复现的正确性问题

优先级 P0：通用 pytest 验证入口以子进程 exit_code=0 作为通过条件。隔离候选模块在导入时调用 `os._exit(0)`，可使包含失败断言的控制面测试没有实际执行，返回仍为 tests_passed，输出为空。探针的容器隔离和回收正常，问题是功能验收的真实性。

证据：`artifacts/project-reviews/2f67b9a4-7af5-419f-91be-bf507b5c2013/report.json`。这不代表先前正常候选的 14 项测试是伪造结果，但确实说明当前通用验证器不能抵抗恶意候选。该复现针对新的通用测试验证入口，不等同于所有已有工单回执、宿主预期值比较或只读验证路径都已被绕过。

修复方向：测试文件置于只读可信位置；候选进程只输出待验证的观测值，由可信父进程核对期望值；提前退出、缺失结果、格式不全和未完成用例均不得计为通过。仅解析“passed”文本或追加一个成功标记仍可被同进程候选代码伪造。

## 后续顺序

1. **P0，验证真实性。** 将上述对抗样例加入回归，修复可信验证边界。
2. **P1，自动运行恢复。** API 与执行进程分离，持久领取、租约/心跳、代际、失联处置及队列指标。现有检查点不是自动调度器。
3. **P1，适配和事务边界。** 接入独立 HTTP mock 业务，验证幂等键、响应丢失、超时和状态前置条件；避免将当前持有任务锁跨业务调用的方案直接套到慢远端接口。
4. **P1，评测说服力。** 场景族分离的开发/保留集、同模型预算下的机制对照、多次真实模型测试及成本/延迟/恢复时长。不得用开发集通过率替代泛化结论。
5. **P2，可用性与扩展。** 统一任务/工具适配接口、报告与 NEEDS_REVIEW 处置入口；再考虑第二个真实模型、流式输出、上下文检索和更细的记忆策略。
